## Platform

web

Responsive: desktop and phone browsers.

## Stack

Delegated: static HTML/CSS with plain JavaScript for the interactions (gallery, reveal, scroll story). There is no deploy target and no existing code, so a no-build static site keeps the work focused on imagery and interaction. Revisit if a deploy target or CMS requirement appears.

## Users

Not yet confirmed. Inferred from the brief: people who would otherwise see the source presentation, such as clients, stakeholders, and prospective clients judging the team's AI image-making. They come to see the final images and to understand how they were made.

## Product Purpose

An interactive website that turns an existing presentation about an AI-generated photography project into an immersive visual experience. Visitors see the final images first, then the technical construction behind each image, then the production methodology, and finally how the system scales.

Success means visitors come away convinced of two things at once:

- **The craft:** every image was art-directed, generated, selected, and refined with care.
- **The system:** the same method repeats and scales into a much larger asset library.

## Positioning

These are not isolated AI images. They come from a structured, repeatable image-generation system: controlled parameters (moment, direction, cast, environment, light, photography, generation, craft) that produce many outputs while keeping one consistent visual identity.

## Operating Context

- The source of truth is a presentation the user will provide. It contains the final images, per-image technical data, workflow, methodology, and supporting material: contact sheets, casting references, workflow screens, generation examples, and retouching examples.
- The experience moves in this order: Final Image → Behind the Image → Behind the Process → Behind the System → Scale.

## Capabilities and Constraints

- Full-screen image gallery with previous/next navigation and an image counter (e.g. `01 / 24`).
- A per-image "behind the image" reveal on hover, showing the technical record: final prompt, AI model, camera reference, lens, focal length, aperture, lighting direction, time of day, location/environment, cast/character reference, wardrobe, composition, photography style, colour treatment, and other parameters or references.
- A methodology story: Creative Direction → Cast → Locations → Wardrobe → Prompt Architecture → AI Generation → Selection → Retouching → Final Asset Library.
- An image-building system with eight parameters: Moment, Direction, Cast, Environment, Light, Photography, Generation, Craft.
- A nine-step production workflow: define the visual world, build the cast, define wardrobe and styling, build the environments, generate, explore variations, select, retouch and craft, deliver.
- A scalability demonstration: 1 Moment → Multiple Directions → Multiple Formats → Hundreds of Assets. It covers compositions, angles, crops, formats, times of day, cast combinations, campaign contexts, and channel uses (social, CRM, web, display, OOH).
- Hover does not exist on touch devices, so the reveal also needs a tap or other touch equivalent.
- Undecided: the project/client name, the image count, which per-image fields exist for every image, and whether the client can be named publicly.

## Brand Commitments

- All content and storytelling come directly from the presentation. Do not invent a separate narrative.
- The photography is always the main focus.

## Evidence on Hand

- None in the repository yet. The presentation is still to be provided.
- Until it arrives, do not fabricate images, prompts, technical parameters, cast, locations, client names, asset counts, or results. Any placeholder must be visibly marked as a placeholder.

## Product Principles

1. The image comes first. Every interaction serves the photography and recedes when it isn't needed.
2. Show the construction. Each image should read as a documented specimen whose making can be traced.
3. Prove the system visually. Scale and repeatability are demonstrated through the material, not just asserted in text.
4. Use the presentation as the source. Restructure it into a narrative, but never add to its facts.
